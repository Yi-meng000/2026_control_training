# F4模板工程架构及规范

## 工程架构

DOCS--->各种文档以及模板工程的使用说明  
Core--->cubemx生成，包含主程序以及各种外设.c  
Drivers--->cubemx生成，各种驱动程序  
APL--->应用层，包含各种应用程序，在此目录下可自定义功能，目前已有/Tasks存放rtos任务的强函数，如要添加功能请在APL目录下新建文件夹存放自定义功能  
FML--->功能模块层，包含各种功能模块以及数学、数据结构函数，现有蓝牙、电磁阀，此外还包含can队列、pid、数学函数、向量结构  
HDL--->板级驱动层，主要有流水灯和蜂鸣器  
IRQ--->中断服务函数，不同类型的中断分别定义了回调。有can1、can2、usart1、usart2、tim2、tim3的中断服务函数  
Motor--->电机驱动层，包含各种电机的驱动程序  
Middleware--->cubemx生成，包含freertos等中间件  
MDK-ARM--->Keil工程文件  
.gitignore git忽略文件移植时注意修改，以减轻仓库体积  

## 工程规范

- 所有代码必须遵循统一的编码规范  
- 每个模块应有清晰的注释  
- 不得破坏现有架构以及层级  

## 现有功能模块

1. 蓝牙模块  
   使用dma单字节接收，数据存入全局变量结构体中，串口1调用  
2. 电磁阀模块  
   使用串口3作为输出，最简版本，不包含对上次调用的感知，根据低四位的状态来直接控制电磁阀板  
3. dji  
   can1FIFO0接收，can1发送，can发送不经过软件队列，过滤器目前仅配置了201-204  
4. ZDrive  
   can2FIFO1接收，can2发送，can发送经过软件队列，过滤器为全通    
5. can  
   can1和can2的过滤器均为，fifo0 201-204，fifo1全通，均配置了两个过滤器  
6. 串口  
   串口1和串口2的dma均已开启，四种调用均已有示例，串口3没有配置，留出供gpio拓展，目前用于电磁阀控制
